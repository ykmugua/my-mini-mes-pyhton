# 测试报告数据库约定

| 项 | 内容 |
|---|---|
| 状态 | 已实现 |
| 日期 | 2026-11-27 |
| 适用范围 | 测试数据统一存储在 `TestReport.db`，库内按工序分表 |

---

## 1. 基本约定

### 1.1 单库分表原则

- 测试数据不放在主库 `mes.db`。
- 所有工序共用一个测试报告数据库：`TestReport.db`。
- 库内按工序分总览表：`report_index_<step_no>`。
- 明细表按工序和条码隔离：`SN_<step_no>_<条码safe>_<hash16>`。
- 工序号来源于主库工序注册（`steps.step_no`）；只读查询不再扫描 `db_1.db` / `db_2.db` 等旧分库。

### 1.2 数据库内部结构

`TestReport.db` 包含两类表：

1. `report_index_<step_no>`：每工序一张测试报告总览表。
2. `SN_<step_no>_<条码safe>_<hash16>`：每工序每条码一张具体明细表。

> 表名中的 `hash16` 为条码 SHA-256 的前 16 位，用于避免条码非法字符、长度和重名问题。

---

## 2. 总览表 report_index_<step_no>

每次整单测试上报写入一行。

字段顺序固定为：`id`、JSON 顶层字段（含 `details` 位置由 `details_table` 内部列占位）、`isfinalreport`、`failed_step`。代码检测到列顺序不一致时自动重建并保留数据。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 自增 id |
| `barcode` | TEXT | 工件条码 |
| `componentcode` | TEXT | 产品型号 |
| `station` | TEXT | 工位 / 测试站编号 |
| `fixturecode` | TEXT NOT NULL DEFAULT '/' | 测试针床码；缺失写 `/` |
| `traycode` | TEXT NOT NULL DEFAULT '/' | 载具号；缺失写 `/` |
| `programname` | TEXT | 测试程序名称 |
| `programversion` | TEXT | 测试程序版本 |
| `testexecutetime` | TEXT | 测试执行时间，原样字符串 |
| `testlongtime` | TEXT | 测试用时，原样字符串 |
| `result` | TEXT | 整单结论 `PASS` / `FAIL`（JSON 顶层字段） |
| `details_table` | TEXT | 指向该产品具体明细表名：`SN_<条码safe>_<hash16>`（内部列） |
| `isfinalreport` | TEXT | 是否最终报告，`true` / `false` |
| `failed_step` | TEXT | 失败项 TestStep；成功为空字符串（内部列） |

索引：

```sql
CREATE INDEX IF NOT EXISTS "idx_report_index_<step_no>_barcode" ON "report_index_<step_no>"(barcode);
```

---

## 3. 具体明细表 SN_<step_no>_<条码safe>_<hash16>

一个产品一张表；每行一条测试明细。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 该产品表内自增 id，从 1 开始 |
| `TestItem` | TEXT | 测试项目 |
| `TestStep` | TEXT | 测试步骤 / 子项 |
| `StandardValue` | TEXT | 标准值 |
| `UpperValue` | TEXT | 上限值 |
| `LowerValue` | TEXT | 下限值 |
| `MeasureValue` | TEXT | 实测值 |
| `TestResult` | TEXT | 单项判定，`true` / `false` |
| `TestBeginTime` | TEXT | 步骤开始时间 |
| `TestEndTime` | TEXT | 步骤结束时间 |

约定：

- 明细表不存 `report_id`。
- 表结构由当前 JSON 明细格式确定；运行阶段格式不变。
- 换项目/换工序如果明细格式变化，只修改该工序库的明细表结构，不影响其他库和主库。
- 不使用 `AUTOINCREMENT`，避免生成 `sqlite_sequence`；使用 `INTEGER PRIMARY KEY` 仍可自增。

---

## 4. 与产品查询页面的关系

产品查询的测试履历分两块：

1. 上方：读取对应工序库的 `report_index`，按条码筛选，点击一行选中报告。
2. 下方：按选中报告的 `details_table` 读取该产品的明细表，列直接来自数据库，不写死；第一列显示自增“序号”。
