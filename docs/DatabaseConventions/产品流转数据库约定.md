# 产品流转数据库约定

| 项 | 内容 |
|---|---|
| 状态 | 已实现 |
| 日期 | 2026-11-27 |
| 适用范围 | 产品当前状态与流转历史；只读/轻量写入 |

---

## 1. 基本约定

### 1.1 分库原则

- 产品流转历史不放在主库 `mes.db`。
- 独立数据库：`ProductFlow.db`
- 库内包含两类表：
  1. `product_overview`：ProductFlow 当前总览表，历史兼容字段；当前在制占用以 `mes.db.active_products` 为准。
  2. `F_<条码safe>_<hash16>`：每个产品一张具体流转表。

### 1.2 命名规则

- 具体流转表：`F_<条码safe>_<hash16>`
  - `条码safe` = 产品条码中非 `[0-9A-Za-z_]` 字符替换为 `_`，最多 40 字符。
  - `hash16` = 产品条码 SHA-256 前 16 位。
- 总览表最后一列保存具体流转表名，作为唯一关联标识。

---

## 2. 总览表 product_overview

一个产品一行，描述当前状态。物理列顺序固定如下，代码检测到列顺序不一致时自动重建并保留数据：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 自增 id |
| `barcode` | TEXT | 板子条码，唯一 |
| `componentcode` | TEXT | 板子型号 / 型号码 |
| `process_code` | TEXT NOT NULL DEFAULT '' | 工艺号 |
| `traycode` | TEXT NOT NULL DEFAULT '/' | 载具号；缺失载具写 `/` |
| `tray_slot` | TEXT NOT NULL DEFAULT '/' | 载具仓位；无仓位写 `/` |
| `board_status` | TEXT | 板状态：`normal` / `lock` / `final` |
| `current_step` | TEXT | 当前所在工序 |
| `last_report_device` | TEXT | 最新切换工序上报的测试设备；手动解锁时填 `手动解锁`（旧名 `current_device` 已重命名） |
| `last_report_note` | TEXT NOT NULL DEFAULT '' | 最新切换备注：`test pass` / `test fail` / 人工填写（解锁时随意） |
| `updated_at` | TEXT | 最新切换流程上报时间 |
| `flow_table` | TEXT | 对应具体流转表唯一标识：`F_<条码safe>_<hash16>` |

索引：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_product_overview_barcode ON product_overview(barcode);
```

---

## 3. 具体流转表 F_<条码safe>_<hash16>

一个产品一张表；每行一次流转事件。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 该产品表内自增 id，从 1 开始 |
| `board_status` | TEXT | 本次流转后的板状态：`正常流转` / `锁死` / `下线` |
| `step_no` | TEXT | 所在工序 |
| `next_step` | TEXT | 下站工序 |
| `device` | TEXT | 切换工序上报的测试设备；手动解锁时填 `手动解锁` |
| `changed_at` | TEXT | 切换流程上报的时间 |

约定：

- 不使用 `AUTOINCREMENT`，避免 `sqlite_sequence`。
- 每个产品的流转表 id 从 1 开始。
- `product_overview` 的 `flow_table` 指向具体流转表。
- 当前状态取总览表；历史流转取具体流转表。

---

## 4. 状态枚举

### 4.1 板状态 board_status

| 值 | 含义 |
|---|---|
| `normal` | 正常流转，产品可继续下一工序 |
| `lock` | 锁死，产品被测试失败或不可信数据锁定，需人工处理 |
| `final` | 终态，产品不再流转 |

### 4.2 device 特殊值

| 值 | 含义 |
|---|---|
| 设备编号 | 测试执行设备上报 |
| `手动解锁` | 操作员人工解锁/放行 |
| 值来自上报 | `last_report_note` 为 `test pass` / `test fail`；解锁时人工填写 |

---

## 5. 与测试报告库的关系

- 产品流转库记录“产品在哪里、状态是什么、怎么切换的”。
- 工序测试库记录“具体测了什么、每步结果如何”。
- 两者通过产品条码、工序、时间关联；不在流转表中复制完整测试明细。

---

## 6. 上报/解锁规则（待实现）

- 测试完成上报时：
  1. 写对应工序测试库（见《测试报告数据库约定》）。
  2. 写 `ProductFlow.db` 的具体流转表一行。
  3. 更新 `product_overview` 当前状态与 `flow_table`。
- 手动解锁时：
  - `device = 手动解锁`
  - `board_status = 正常流转`
  - 写一行流转记录并更新总览表。

> 实现说明：测试上报（V1.3）与工序解锁均会写流转表并更新总览表；解锁不会覆盖 `traycode`。

> 当前实现：托盘解绑表示产品下线。系统会写入一条 `托盘解绑` 流转历史，删除 `active_products` 当前在制记录，并兼容清理 `ProductFlow.product_overview`；测试报告、测试数据和产品追溯档案不会被删除。终态测试上报也会从当前在制表移除产品。
