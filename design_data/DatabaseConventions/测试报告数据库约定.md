# 测试报告数据库约定

| 项 | 内容 |
|---|---|
| 状态 | 约定稿 |
| 日期 | 2026-11-18 |
| 适用范围 | 测试数据按工序分库存储；产品查询/追溯只读 |

---

## 1. 基本约定

### 1.1 分库原则

- 测试数据不放在主库 `mes.db`。
- 每个工序建立一个独立测试报告数据库。
- 数据库命名：`db_<工序号>.db`
  - 例：`db_1.db`
  - 工序号来源于主库工序注册（`steps.step_no`）；工序号只允许英文字母和数字。
- 工序号和工序名在页面输入时只允许**英文字母和数字**；如已有中文工序名，需在启用该约定前转换为英文/数字命名。
- 修改工序号时，必须同步重命名对应数据库文件，并更新所有引用该库的配置/索引；修改工序名不影响数据库文件名。

### 1.2 数据库内部结构

每个工序库结构和当前 `TestReport.db` 一致，包含两类表：

1. `report_index`：测试报告总览表。
2. `SN_<条码safe>_<hash16>`：每个产品/条码一张具体明细表。

> 表名中的 `hash16` 为条码 SHA-256 的前 16 位，用于避免条码非法字符、长度和重名问题。

---

## 2. 总览表 report_index

每次整单测试上报写入一行。

字段顺序与 `mesUploadTestDataFormat.json` 顶层字段保持一致（系统列 `id` 在前，`failed_step`/`details_table` 为内部附加列在后）。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 自增 id |
| `linecode` | TEXT | 产线代码 |
| `station` | TEXT | 工位 / 测试站编号 |
| `componentcode` | TEXT | 型号码 |
| `traycode` | TEXT | 托盘码；上报可选，为空存 `''` |
| `barcode` | TEXT | 产品条码 |
| `programname` | TEXT | 测试程序名称 |
| `programversion` | TEXT | 测试程序版本 |
| `testexecutetime` | TEXT | 测试执行时间，原样字符串 |
| `testlongtime` | TEXT | 测试用时，原样字符串 |
| `result` | TEXT | 整单结论 `PASS` / `FAIL`（JSON 顶层字段） |
| `isfinalreport` | TEXT | 是否最终报告，`true` / `false` |
| `failed_step` | TEXT | 失败项 TestStep；成功为空字符串（内部列） |
| `details_table` | TEXT | 指向该产品具体明细表名：`SN_<条码safe>_<hash16>`（内部列） |

索引：

```sql
CREATE INDEX IF NOT EXISTS idx_report_index_barcode ON report_index(barcode);
```

---

## 3. 具体明细表 SN_<条码safe>_<hash16>

一个产品一张表；每行一条测试明细。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 该产品表内自增 id，从 1 开始 |
| `TestItem` | TEXT | 测试项目 |
| `TestStep` | TEXT | 测试步骤 / 子项 |
| `StandardValue` | TEXT | 标准值 |
| `UpperValue` | TEXT | 上限值 |
| `LowerValue` | TEXT | 下限值 |
| `MeasureValue` | TEXT | 实测值 |
| `TestResult` | TEXT | 单项判定，`true` / `false` |
| `TestBeginTime` | TEXT | 步骤开始时间 |
| `TestEndTime` | TEXT | 步骤结束时间 |

约定：

- 明细表不存 `report_id`。
- 表结构由当前 JSON 明细格式确定；运行阶段格式不变。
- 换项目/换工序如果明细格式变化，只修改该工序库的明细表结构，不影响其他库和主库。
- 不使用 `AUTOINCREMENT`，避免生成 `sqlite_sequence`；使用 `INTEGER PRIMARY KEY` 仍可自增。

---

## 4. 与产品查询页面的关系

产品查询的测试履历分两块：

1. 上方：读取对应工序库的 `report_index`，按条码筛选，点击一行选中报告。
2. 下方：按选中报告的 `details_table` 读取该产品的明细表，列直接来自数据库，不写死；第一列显示自增“序号”。
